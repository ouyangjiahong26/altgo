# 离线资产包：无外网机器的一次性交付，挂在固定 tag 的独立 Release 上

altgo 的安装包只含应用本体，转写模型、润色模型与润色运行时都按需下载（ADR-0010），一台完全没有外网的机器装完运行不起来。这类目标机只有一个获取途径，就是把文件搬过去。决定：

- 发布一个离线资产包，挂在固定 tag（本次是 `offline-assets-v2.7.8`）的独立 Release 上。包内含 Windows x64 的 NSIS 安装器、转写模型 `sense-voice`、润色模型 `qwen3-0.6b`、润色运行时（llama.cpp b11612 的 x64 产物）、放置脚本、整包 SHA-256 清单与第三方许可证清单。另提供带微软 WebView2 离线安装器的变体，供 Windows 10 目标机使用，Windows 11 自带 WebView2 取不带的那份。
- 资产包不进安装器，也不改版本 Release 的产物清单与更新路径。ADR-0010 否决“把运行时放进 `bundle.externalBin`”的两条理由在这里同样成立，而且内嵌解决不了目标机的问题：那台机器连安装器本身都要靠搬运。
- 包内脚本只把 `models`、`polish-models`、`runtime` 三个目录复制进 `%APPDATA%\altgo`，逐文件比对 SHA-256，相同跳过、不同覆盖并提示，不修改 `altgo.toml`，不自动拉起安装器。首装与升级都不会覆盖用户已有配置与 API key。
- tag 随应用版本走，因为 zip 内嵌了安装器。模型或润色运行时变更时也要重新出包，这两项与应用的版本节奏不同步。

## 备选方案

- 把模型与运行时打进安装器。被否决。理由与 ADR-0010 的 `bundle.externalBin` 一条相同，安装后磁盘上存两份，且每个版本更新都要多下 500 MB 级内容。
- 把 `tauri.conf.json` 的 `webviewInstallMode` 改成 `offlineInstaller`。被否决。Tauri 会把 WebView2 离线安装器打进每一个安装器，此后每个版本、每个架构都增重约 204 MB，而 WebView2 只需装一次。本次实测该离线安装器为 214090448 字节，Tauri 配置 schema 里写的约 127 MB 是旧口径，体积随 WebView2 版本增长。
- 让应用除配置目录外也从安装目录读模型与运行时。被否决。要改 `model.rs`、`polish_model.rs` 与 `polish_runtime/manifest.rs` 三处路径解析，还要同步设置页的“已下载”判定，而收益只是省一次复制。
- 挂在版本 Release 上，每版重新生成。被否决。模型与运行时的哈希、构建号都写死在代码里，不随应用版本变化，每版重发 500 MB 级内容没有意义，也会让版本 Release 的产物校验与 checksums 范围变复杂（ADR-0008 的产物精简取向）。
- 只把目录结构交出去，由使用者手工复制。作为兜底保留，但顺序与目标路径都容易记错，且没人愿意对着一份说明逐个目录核对哈希。

## 后果

- 与 ADR-0008 的关系：新增一类对外发布的产物。它符合“每个发布产物都必须有明确消费者”，消费者是无外网环境的运维，代价是 Release 列表里多一个与被精简原则无关的常驻页面。
- 与 ADR-0010 的关系：安装包内容与更新路径都没动，ADR-0010 的决策句与后果表述仍然有效，这里只是补一条搬运通道。
- 每次要支持新版本的无外网交付就要重切一次包。模型与运行时没变时，那部分内容可以原样复用，只有安装器与版本号要换。
- 转写模型适用 FunASR Model Open Source License Agreement，随包分发给第三方必须注明出处并保留模型名称；llama.cpp 的 Windows 产物里只有 `LICENSE-LLVM-OpenMP`，没有 MIT 正文，需要自行补齐。两份文本都进包内的第三方许可证清单。
- WebView2 离线安装器的体积与哈希随版本变化，重切包时要重新记录，不能沿用上一次的数字。
- WebView2 安装器受微软自己的许可约束，允许的范围是随应用一起分发，不允许作为独立下载项转载。因此它只出现在含 altgo 安装器的那个 zip 里，永不单独挂成发布产物，Release 正文与包内说明都写成“altgo 离线包的一部分”。包内第三方清单要带该许可的快照与抓取日期，并按条款 §9 给出 SmartScreen 会向微软发送信息的通知。安装器本身不得改名或重打包。
