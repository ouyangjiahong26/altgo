# ADR-0016：用户自设术语表走润色 prompt，不做默认的转写后替换

- 状态：已接受（2026-11-02）
- 日期：2026-11-02
- 受影响模块：`src-tauri/src/config.rs`, `src-tauri/src/polisher/{glossary,formatter,transport}.rs`, `src-tauri/src/cmd.rs`, `frontend/`
- 依据：#323 的评估报告与 #324

## 背景与问题

领域术语经常被转写成同音字，例如把地月空间写成地约空间、缔约空间或地阅空间。用户没有地方声明标准写法，每次都要手动改。sherpa-onnx 的 `hotwords_file` 只被 transducer 与 nemo_transducer 读取，本地两个 CTC 引擎用不上。`hr` 同音替换器只覆盖本地引擎，而且需要从标准写法生成发音词典与 FST。

#323 在 965 条本机历史、34 条定向句、60 条硬负例与 60 条普通句上比较了几条路径。当前 `heavy` 不加术语表修正 12/24 条定向句，加 10 条只含标准写法的术语表后修正 24/24。温度 0.3 时 `缔约空间` 两条硬负例重复 5 次出现 6 次误替换，温度 0 降到 0 次。大模型的任何术语插入率是 23.3%，其中 `航天飞机` 改成 `航天器`、`地月拉格朗日力学` 改成 `地月拉格朗日点力学` 改变了原意。拼音替换在 `none` 档修正 24/24，但硬负例同音误替换 13.3%（10 条术语表）到 23.1%（200 条），200 条时出现 `需要控制` 改成 `需遥控制`、`约是` 改成 `月食`。先替换再润色会把错误固化。

## 决策

1. 配置新增 `[polisher] glossary`，字符串数组，只填标准写法。第一版限制 50 条，单条不超过 32 个字符，拒绝空项、重复项与换行。
2. 术语表只对远端润色的 `medium` 与 `heavy` 档生效。解析出 system prompt 后追加术语表说明与词条，术语表非空时请求温度固定为 0，不再使用配置里的 `temperature`。
3. 输出下发前做一次后置检查。输出里出现输入没有、也没有同音来源的术语表词时，去掉术语表重试一次。重试只发普通 prompt，不再过检查。这样 `航天飞机` 改成 `航天器`、`地月拉格朗日力学` 改成 `地月拉格朗日点力学` 这类没有语音依据的改写不会落到剪贴板。
4. `none` 档不默认开启拼音替换。报告里的 13.3% 到 23.1% 误替换不可接受。若以后要覆盖 `none`，只对 3 字以上术语启用，术语表限制在 10 到 20 条，并用 `探测气球`、`探测气体`、`缔约空间` 做回归测试，硬负例误替换率超过 1% 就不发布。
5. 本地润色暂不使用术语表。本地模型与小样本行为没有评估，`LocalPolisher` 继续用短提示词与保真校验。
6. 后置检查用 `pinyin` crate 做无声调拼音匹配。输入里存在同音且等长的片段时视为合理纠错，不拦。同音但语义正确的片段（`缔约空间`）匹配也会通过，这类情况靠温度 0 与 prompt 约束，后置检查不负责区分语义。后置检查只覆盖中文术语。英文术语仍会进入 prompt，但拼音匹配直接跳过，不能拦住英文术语插入。英文的同音词更少，近音词与专名误识更常见，需要单独的语料与校验方式。

## 备选方案

- 转写后拼音替换作为默认路径。被否决。10 条术语表已有 13.3% 硬负例误替换，200 条到 23.1%，而且会命中 `需要控制`、`约是` 这类普通短语。
- 精确变体替换。被否决。要求用户填变体，与“只填标准写法”的输入形状冲突，用户也不会知道要填哪些变体。
- sherpa-onnx `hr` 同音替换器。被否决。只覆盖本地引擎，且需要预生成发音词典与 FST，不能随用户术语表在运行时更新。
- 先替换再润色。被否决。替换会把 `缔约空间` 这类正确片段改坏，大模型看到的是已经改过的文本，无法恢复。
- 大模型输出完全信任。被否决。23.3% 的任何术语插入率里有多条改变原意的改写，需要后置检查兜底。

## 后果与权衡

### 正向收益

- 用户只填标准写法就能覆盖真实历史错例，10 条术语表在评估里把定向修正率从 50% 提到 100%。
- 温度 0 消除了测试里的 `缔约空间` 误替换，后置检查挡住了没有同音来源的术语插入。
- 术语表跟随用户配置，只发给用户已经配置的润色服务。成本约为每千条请求 0.3 美元，延迟增加在网络波动范围内。
- 不需要新模型、新运行时或新进程，复用现有远端润色链路。

### 代价与局限

- 术语表只在润色开启时生效。`none` 档用户仍然要手动改术语，`light` 档也不使用术语表。
- 后置检查依赖拼音匹配，只能挡没有同音来源的插入。`探测气球` 改成 `探测器球`、`缔约空间` 改成 `地月空间` 这类同音但语境错误的替换仍可能发生，温度 0 只能降低概率。英文术语没有拼音后置检查，英文近音词与专名误识也还没有评估。
- 术语表会进入 system prompt，条数越多 prompt 越长。50 条是人为上限，超过后模型遵循度与小模型预填成本都没有评估。
- 本地润色不生效。用户切到本地引擎时术语表静默失效，设置页文案需要说明。
- 新增 `pinyin` crate，增加二进制体积与一条维护依赖。它只用于后置检查，不参与转写或解码。
