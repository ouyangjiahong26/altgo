# 保真校验只在本地档启用，本地档失败不回退云端

小模型做文本整理的过编辑与幻觉有公开实测记录，本机复现也一致：0.6B 把“GitHub 的那个 project”译成“GitHub 项目”，1.7B 把 132 字压成 60 字丢掉半句，0.3B 直接把“我。”续写成“我有什么我可以帮你做的？”。同时本地档的隐含承诺是文本不离开本机。两条合起来要求对本地输出设一道闸门，并明确失败时往哪降。决定：

- 保真校验只在本地档启用，云端档行为保持不变。四条硬规则如下。数字、URL、路径必须逐字保留。汉字数比越出 0.5 到 1.6 判失败。输出里未在输入出现过的汉字占比超过 0.25 判失败。模板标记、emoji、Markdown 与 AI 套话泄漏判失败。ASCII 单词变化只写日志，不判失败。
- 校验不过时回退转写原文，复用现有 `polish_failed` 路径与 `polish-failed` 事件，界面表现与云端失败一致。
- 本地档不可用（运行时被杀、模型缺失或哈希不符、启动超时）时同样回退转写原文，不自动改用云端档。设置页保留状态，首次发生给一次可见提示。
- 不提供让用户关闭校验的开关。

## 备选方案

- 本地档不可用时自动改用云端档。被否决。用户选本地档时的心智是内容不外发，静默改走云端等于在用户以为离线时把文本送上网。
- 保真校验在所有档统一启用。被否决。云端档已长期运行，用户当前配置就是 heavy，行为突变会被当成回归，且云端模型触发这四条的比例很低，收益不抵风险。
- 把“每个 ASCII 词必须逐字出现在输出里”也列为硬规则。被否决。口头转写里的 `lininux` 改成 `Linux` 是期望的纠错，这条规则会把它误杀。
- 给用户一个关闭校验的开关。被否决。校验是本地档的质量下限机制而非偏好项，可关之后“本地润色改乱了”的责任边界就说不清。

## 后果

- 本地档的失败对用户呈现为“结果就是原文”，与“润色本来没什么可改”在界面上难以区分，因此运行时或模型不可用必须有可见状态，否则用户会以为功能已经生效。
- 专名被翻译这类改动不触发校验，属于已知残留风险，缓解手段是提示用户换用 1.7B 档，或在后续版本补充专名保护规则。
- 校验规则会随模型与语料变化调整，规则改动不需要改配置面，因为不暴露给用户。
