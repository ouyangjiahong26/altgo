# ADR-0017：候选术语筛选走远端润色服务，只建议不自动写入

- 状态：已接受（2026-11-02）
- 日期：2026-11-02
- 受影响模块：`src-tauri/src/polisher/`、`src-tauri/src/cmd.rs`、`frontend/src/components/history/`、`frontend/src/pages/settings/`、`docs-site/`
- 依据：#326、ADR-0016

## 背景与问题

#324 与 ADR-0016 加入了用户自设术语表，远端 `medium` 与 `heavy` 档会把标准写法追加到 system prompt。用户发现术语写错时通常是在历史列表里，不在设置页。要修正一个词，他得先记住正确写法，再切到设置页手动输入。历史条目没有把“这条转写可能错在哪个词”与“把它加入术语表”连起来。

#323 的评估显示，10 条标准写法能把测试集的术语错误全部修正，但模型也会把同义或正确片段改成术语。候选筛选因此不能自动写入，必须由用户逐条确认。

## 决策

1. 历史条目在含汉字时显示“检查术语”入口。纯英文条目不显示，第一版只筛选中文术语。入口打开历史条目内的页内面板，不新建模态框。
2. 候选筛选只走远端润色服务。要求 `[polisher] backend = "remote"`，且 `api_base_url`、`model`、`api_key` 齐全，不看润色档位是否为 `none`。`backend = "local"` 时不发请求，即使配置里还留着远端地址与密钥。面板给出可操作提示，手动输入仍可用。
3. 只发送用户点开的那一条历史条目。发送 `rawText`，`text` 与 `rawText` 不同时再发送 `text`，并标明两段的关系。不发送历史列表、不发送当前术语表。
4. 候选请求使用独立短提示词，温度 0，`max_tokens` 512，强制关闭思考。提示词写成 Rust 常量，不放进未随安装包分发的 `resources/prompts/`。模型一行输出一个候选，用制表符分隔标准写法与原文片段，解析容忍编号、项目符号与缺失片段，最多保留 20 条。
5. AI 只给候选。用户勾选候选，也可以在同一个面板里手动补充术语。加入时去重，遵守单条 32 字符与总计 50 条上限，复用现有 `validate_glossary` 与 `save_config`，不修改历史条目的 `text`。
6. 加入成功后保留面板，移除已加入的候选，显示已加入条数，没加入的词标出原因。设置页重新进入时读取 `get_config`，看到新词。
7. 隐私文档在中英两份页面新增候选筛选小节，说明选中的历史条目文本会发送到用户配置的远端服务。面板在请求前显示一行发送提示。

## 备选方案

- 本地润色模型生成候选。否决。本地模型没有候选筛选的评估，而且 `backend = "local"` 是用户对文本不外发的选择。
- 自动把候选写入术语表。否决。#323 显示模型会把同义或正确片段改成术语，用户确认是必要防线。
- 候选输出用 JSON。否决。issue 要避开额外的解析失败面，一行一个候选更稳。
- 候选 prompt 包含当前术语表。否决。术语表会给模型锚点，提高把正确片段改成术语的概率，重复项由客户端过滤。
- 新增独立模型或运行时。否决。复用现有远端润色客户端，不增加下载与运行时。

## 后果与权衡

- 每次点“检查术语”会增加一次远端请求与费用，只发送一条历史文本。
- 本地润色用户不能使用 AI 候选，只能手动输入。这是隐私选择的直接结果。
- 候选质量取决于用户配置的模型。面板与隐私文档要说明 AI 只给建议，用户逐条确认。
- 加入术语表走 `save_config`，和保存设置一样会重启流水线，录音或转写进行中调用会中断当前任务。
- 历史条目文本不被修改，术语表只影响后续转写。
