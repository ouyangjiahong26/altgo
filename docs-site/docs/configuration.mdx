# 配置指南

altgo 使用 TOML 格式的配置文件，所有字段都有默认值，只需修改你需要的部分。

# Configuration Guide

altgo uses a TOML configuration file. Every field has a default value, so you only need to change the parts you care about.

## 配置文件位置

`~/.config/altgo/altgo.toml`

## Polisher Configuration

altgo supports polishing transcribed text through an LLM.

### 润色级别

| 级别 | 效果 | 需要 API 密钥 |
|------|------|:---:|
| `none` | 不润色，直接输出转写文本 | 否 |
| `light` | 修正标点和错别字 | 是 |
| `medium` | 修正语法、改善语序通顺度 | 是 |
| `heavy` | 结构化重写，适合正式文档 | 是 |

### Polishing Levels

| Level | Effect | Needs API key |
|------|------|:---:|
| `none` | No polishing; the raw transcription is output as-is | No |
| `light` | Fix punctuation and typos | Yes |
| `medium` | Fix grammar and improve fluency | Yes |
| `heavy` | Structured rewriting, suited to formal documents | Yes |

### 配置示例

```toml
[polisher]
level = "medium"
protocol = "openai"
api_key = "sk-your-key"
api_base_url = "https://..."
model = "your-model"
```

### `api_base_url` 写法

两种写法都支持，应用会自动拼出正确的请求地址：

- **不带版本路径**（origin）：如 `https://api.deepseek.com`、`https://api.anthropic.com`，自动补 `/v1/chat/completions` 或 `/v1/messages`；
- **带版本路径**：如 `https://api.moonshot.cn/v1`、`https://open.bigmodel.cn/api/paas/v4`、`https://dashscope.aliyuncs.com/compatible-mode/v1`，只在后面接 `/chat/completions` 或 `/messages`。

也可以直接填完整 endpoint（以 `/chat/completions` 或 `/messages` 结尾），此时原样使用。

设置页的「润色」分区有**测试连接**按钮：选好供应商预设、填入密钥后点击，会立即发一次最小请求并给出可读的结果（密钥无效、地址不对、超时等），无需先保存或实际录音验证。

### The `api_base_url` Format

Both forms are supported; the app automatically assembles the correct request URL:

- **Without a version path** (origin): e.g. `https://api.deepseek.com`, `https://api.anthropic.com`; `/v1/chat/completions` or `/v1/messages` is appended automatically;
- **With a version path**: e.g. `https://api.moonshot.cn/v1`, `https://open.bigmodel.cn/api/paas/v4`, `https://dashscope.aliyuncs.com/compatible-mode/v1`; only `/chat/completions` or `/messages` is appended.

You may also paste a full endpoint (one ending in `/chat/completions` or `/messages`); it is then used verbatim.

The "Polishing" section of the Settings page has a **Test Connection** button: pick a provider preset, fill in the key, and click it — a minimal request is sent immediately with a readable result (invalid key, wrong URL, timeout, etc.), without saving first or doing an actual recording.

### 默认关闭「思考」

语音润色是轻量文本任务，推理模型先「思考」再回答会凭空多出数秒延迟和 token 花费。对支持关闭思考的服务商，应用会自动在请求中附带关闭参数，无需配置：

| 服务商 | 自动附带的参数 |
|---|---|
| 通义（dashscope）、SiliconFlow（.cn / .com） | `enable_thinking: false` |
| 智谱（bigmodel.cn / z.ai）、火山方舟、MiniMax、DeepSeek、Moonshot、Kimi | `thinking: {"type": "disabled"}` |
| OpenRouter | `reasoning: {"enabled": false}` |

其他服务商（OpenAI、Anthropic、千帆、Gemini、Ollama）的推荐模型默认不思考，无需处理。注意个别强制思考的模型（如智谱 GLM-5.3）不接受关闭参数，选择预设推荐的模型即可避开。对未命中上表的中转端点，应用还会在出口剥掉响应中混入的 `<think>` 思维链残渣（Anthropic 协议取第一个文本块），避免其进入剪贴板。

环境变量覆盖密钥：

```bash
export ALTGO_POLISHER_API_KEY="sk-your-key"
```

### Thinking Disabled by Default

Voice polishing is a lightweight text task; reasoning models that "think" before answering would add seconds of latency and token cost for nothing. For providers that support turning thinking off, the app automatically attaches the disable parameter — no configuration needed:

| Provider | Parameter attached automatically |
|---|---|
| Tongyi (dashscope), SiliconFlow (.cn / .com) | `enable_thinking: false` |
| Zhipu (bigmodel.cn / z.ai), Volcano Ark, MiniMax, DeepSeek, Moonshot, Kimi | `thinking: {"type": "disabled"}` |
| OpenRouter | `reasoning: {"enabled": false}` |

Recommended models from other providers (OpenAI, Anthropic, Qianfan, Gemini, Ollama) do not think by default, so nothing is needed. Note that a few forced-thinking models (e.g. Zhipu GLM-5.3) reject the disable parameter — simply choose a preset-recommended model to avoid them. For relay endpoints not covered by the table above, the app also strips stray `<think>` chain-of-thought residue from responses on the way out (for the Anthropic protocol it takes the first text block), keeping it out of your clipboard.

Override the key via environment variable:

```bash
export ALTGO_POLISHER_API_KEY="sk-your-key"
```

## 按键配置

与 [`configs/altgo.toml`](https://github.com/cislunarspace/altgo/blob/master/configs/altgo.toml) 一致；默认触发键为 **右 Alt**。若在设置页使用「按下以设置」，Linux 会写入 `linux_evdev_code` 字段。

```toml
[key_listener]
key_name = "Alt_R"                 # 触发键（示例：右 Alt；左 Alt 可用 Alt_L）
long_press_threshold_ms = 200      # 长按判定阈值 (ms)
double_click_interval_ms = 300     # 双击判定间隔 (ms)
min_press_duration_ms = 100        # 最短按下时长，过滤 IME 抖动
```

## Key Binding Configuration

Consistent with [`configs/altgo.toml`](https://github.com/cislunarspace/altgo/blob/master/configs/altgo.toml); the default trigger key is **right Alt**. If you use "Press to set" on the Settings page, Linux writes the `linux_evdev_code` field.

```toml
[key_listener]
key_name = "Alt_R"                 # 触发键（示例：右 Alt；左 Alt 可用 Alt_L）
long_press_threshold_ms = 200      # 长按判定阈值 (ms)
double_click_interval_ms = 300     # 双击判定间隔 (ms)
min_press_duration_ms = 100        # 最短按下时长，过滤 IME 抖动
```
